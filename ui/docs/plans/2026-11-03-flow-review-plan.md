# 사용자 흐름도 재정비 작업 계획

> **실행하는 에이전트에게:** 이 계획은 작업 단위로 실행한다. 단계는 체크박스(`- [ ]`)로 진행 상황을 표시한다.

**목표:** 팀 게임의 모든 화면을 담은 FigJam 흐름도(전체 1장 + 상세 5장)를 만들고, 상자마다 와이어프레임 번호와 상태를 달아 다음 단계의 검증 체크리스트로 쓴다.

**구조:** 먼저 팀 레포에서 화면 목록 표(`flow-inventory.md`)를 만들어 사용자 확인을 받는다. 그다음 그 표를 그대로 FigJam 섹션으로 옮긴다. 섹션마다 스크린샷으로 확인한다.

**도구:** Figma MCP(`use_figma` + `figma-use`·`figma-use-figjam` 스킬, `get_figjam`, `get_screenshot`), 팀 레포 읽기(사용자 컴퓨터 `device_bash`)

**설계 문서:** `ui/docs/specs/2026-11-03-flow-review-design.md`

## 전체 제약

- FigJam 파일: `nHfGBYZsYIcHNUD9SU4cGs`. 와이어프레임 파일 `qjL5PNYHPgTDQ0huZXBzLg`은 읽기만 한다.
- 기준: 사용자가 방향을 정한 부분(타이틀, 챕터 진행)은 사용자 안을 본 흐름으로 그리고, 팀 현재 구현은 메모로 단다. 나머지는 팀 레포 기준으로 그린다.
- 팀 레포는 읽기만 한다. 시작할 때 최신 커밋을 기록하고, 섹션마다 "팀 레포 기준: <커밋> (날짜)"를 적는다.
- 상자 표기: `이름 / 한 줄 목적 / WF 번호 · 상태`. 상태는 `맞음` / `수정` / `수정 (팀 현재 구현엔 맞음)` / `없음` / `이전안만 있음` 중 하나.
- 목표(미구현) 규칙은 점선 상자로, 팀 현재 구현 메모는 한 가지 색으로 그린다. 기존 범례 색(파랑·노랑·보라·빨강·초록)은 유지한다.
- 기존 섹션은 지우지 않고 이름만 "이전안 · 2026-11-03 전 · …"으로 바꾼다.
- 레포 commit·push는 사용자 승인 뒤, bundle을 거쳐 사용자가 한다.

## 검토할 때 볼 것

1. **화살표 겹침과 역방향.** 섹션마다 스크린샷을 찍어 선이 상자를 가로지르거나 오른쪽→왼쪽으로 되돌아가는 곳이 없는지 본다. 반복 동선은 양쪽 화살표나 문장으로 처리한다.
2. **상자 글자 넘침.** 세 줄 표기가 상자 밖으로 나가지 않는지 스크린샷으로 확인한다.
3. **와이어프레임 번호 오대응.** 표의 WF 번호를 피그마 프레임 이름(`get_metadata` 0:1)과 다시 대조한다.
4. **팀 레포 갱신.** 작업 중 팀 커밋이 바뀌면 바뀐 문서 diff만 보고 표를 고친다.
5. **메모와 목표 점선의 혼동.** 범례에 "실선 = 본 흐름, 점선 = 팀 목표(미구현), ○색 메모 = 팀 현재 구현"을 섹션마다 적는다.
