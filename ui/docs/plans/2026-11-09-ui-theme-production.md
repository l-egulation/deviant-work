# Deviant 후속 UI 제작 계획

> 실행: executing-plans 방식으로 현재 세션에서 직접 진행. 아래 체크박스로 산출물과 검증을 추적한다.

**Goal:** 현행 흐름도에 필요한 화면을 동일 테마·실제 에셋으로 순서대로 완성한다.
**Architecture:** 기능 기준은 Figma 현행 와이어와 팀 문서를 대조하고, 시각 기준은 승인된 PNG/폰트/어두운 열린 레이아웃을 유지한다. Unity 적용 전 검토용 HTML과 실제 렌더 이미지를 만든다.
**Tech Stack:** 정적 HTML/CSS/JS, 기존 PNG 에셋, MemomentKkukkukk 폰트.
**Spec:** ../../work/reviews/2026-11-09-flow-theme-backlog.md 및 Figma 128:128,128:224.

## 공통 기준
- Unity/Figma 원본 수정 없음. work/ui-design에 기록·시안을 업로드.
- 화면 크기1920×1080, 좌우 기본 여백150px. 960×540에서도 확인.
- 기존 병/문양/무기/팔레트/선택 획 에셋 재사용. 가짜 도형 아이콘으로 대체하지 않음.
- 이름과 효과, 처리 상태와 행동은 간격/정렬로 구분. 색만으로 구분하지 않음.
- 화면 단위로 검토하며 모든 UI를 한 번에 만들지 않음.

## 검토 초점
1. 좌측 몰림과 오른쪽 과한 여백: 전체 화면으로 확인.
2. 긴 설명: 문장이 잘리거나 행동과 겹치지 않는지 확인.
3. 빈 칸/장착된 칸: 바탕/칠/문양의 상태가 일치해야 함.
4. 현재/후보 효과: 서로 뒤섞이거나 적용 완료로 오해되지 않아야 함.
5. 미정 수치/가방 규칙: 예시와 확정 동작을 구분.

## 이후 순서와 완료 기준
1. 정비소 거래 상태: 강화/색 변경/판매/파괴의 전후·부족·최대·취소. 스탬프는 현재 기능 범위를 확인한 뒤 진행. 대표 화면 승인 후 다음 작업으로.
2. HUD/지도/일시정지: 탐험→상호작용→가방→복귀 연결, 보스 HUD·포탈·열쇠 포함.
3. 마을 시설/출발 준비: 보급소·염색공방·회수공방·도면 선택. 가능/잠김/부족/완료 상태.
4. 보스 제단/결과: 색→잉크 선택, 사망/클리어/마을 잉크와 해금 안내.
5. 타이틀/설정/제작진 및 대사·첫런 안내. 공통 키캡·확인·취소 패턴 재사용.
6. Unity 전달 준비: 확정 에셋, 크기/피벗/입력/상태/복귀 규칙 패키지. 별도 요청 전 Unity 적용 금지.

## 이번 판단과 한계
- Figma는 회색 오른쪽 패널이지만 사용자가 승인한 테마 방향에 따라 열린 전체화면 배치로 재해석한다.
- 3칸 기본 예시, +0 효과 사용. 강화50G·변경권1은 와이어의 예시이며 거래 확정값이 아니다.
- 가방 용량/스탬프/강화 효과 계산은 충돌 해결 전 구현하지 않는다.
