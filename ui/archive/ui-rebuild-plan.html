00 / 출발점

무엇을 새로 설계하는가

도면으로 무기를 정하고, 흰색·검정 잉크와 팔레트로 전투 방식을 구성한다. 짧은 전투에서 그 차이를 체감하고 다음 선택으로 이어지는 경험.

최신 제안의 구성

도면은 기본 무기 종류, 흰색 잉크는 형태, 검정 잉크는 특수 공격을 정한다. 별도 팔레트의 색상 칸에는 추가 효과 파츠를 넣는다. 직접 강화하는 대상은 도면뿐이다.

팔레트 없이도 도면 무기를 쓸 수 있고, 팔레트는 일부 칸만 채워 활성화할 수 있다. 전투 중에는 현재 손에 든 무기의 팔레트 효과만 적용한다.

아직 결정하지 않은 것

최신안의 검·둔기·원거리와 이전의 4계열 사이 관계, 장착 무기 수의 최종 유지 여부, 게임 시작·런 종료 흐름, 획득과 경제, 정확한 비용·수치·콘텐츠 수, 저장·영구 해금.

10월 14일 로컬 플레이테스트는 새 제작 규칙이 구현된 게임으로 취급하지 않는다.

이 문서의 사용 원칙
가설은 관찰로 확인하기 전까지 가설이다. 이미지 시안은 의사소통 자료이고, 플레이어의 이해와 재미는 실제 조작을 통해 확인한다.
01 / 진행 지도

아래층부터 위층으로, 두 번 검증

목표와 가설→플레이어 이해→범위→선택 흐름→화면 골격→시각 언어→플레이 검증

첫 번째 검증 · 문제와 기대

시안을 보여주기 전에 장르 경험이 있는 플레이어의 실제 선택 경험을 듣는다. 무엇이 헷갈리고, 어떤 선택이 다시 해볼 동기를 주는지 확인한다.

두 번째 검증 · 사용과 체감

간단한 정비 시제품과 플레이 가능한 전투 구간을 직접 조작하게 한다. 설명 없이 선택할 수 있는지, 선택한 차이가 전투에서 느껴지는지 기록한다.

워크북의 순서를 게임 설계에 맞춰 풀어 썼다. 각 단계의 아래 칸에 결정·근거·남은 질문을 기록하면 된다.

01-A / 전체 플레이 흐름 · 제안

첫 화면에서 다음 정비까지

아래는 아직 결정되지 않은 게임 시작·런 구조를 논의하기 위한 첫 안이다. 제작소 시연의 내부 동작을 게임 전체 흐름으로 확대해 확정하지 않는다.

타이틀→짧은 첫 전투→첫 정비→다음 구간 출발→전투·보상→정비 반복→런 결과

왜 첫 전투를 먼저 두는가

플레이어가 기본 공격과 특수 공격을 직접 써본 뒤 형태·효과를 고르면, 정비 화면의 선택이 실제 경험과 연결된다. 첫 전투는 설명을 최소화하고 짧게 설계하는 안이다.

왜 첫 정비를 따로 두는가

도면, 흰색·검정 잉크, 팔레트를 한 번에 소개하면 복잡할 수 있다. 처음에는 도면과 형태·특수 공격만 보여주고, 색상 팔레트는 보상 획득 후 소개하는 단계적 공개를 시험한다.

초기 화면 목록 제안

타이틀 · 시작/이어하기/설정/종료 → 첫 전투 · 이동·공격·회피 안내와 최소 HUD → 정비 허브 · 현재 무기와 다음 행동 요약 → 도면 작업대 · 무기·흰색·검정 설정 및 도면 강화 → 팔레트 작업대 · 색상 칸 채우기, 굽기, 부분 수정, 재제작 → 출발 확인 · 현재 구성 요약 → 전투 · HUD/일시정지 → 구간 결과 · 보상과 다음 정비 진입 → 런 결과 · 획득·실패·재시작 요약.

결정 전 확인할 것
첫 구간을 미리 정한 무기로 시작할지, 시작 전에 도면 하나를 고르게 할지. 두 무기 장착이 최신 체계에서도 유지되는지. 보상·죽음·영구 해금이 어떤 구조인지. 이 답에 따라 타이틀·결과·보관 UI가 달라진다.
02 / 전략층

목표와 가설

화면을 그리기 전에, 좋은 UI가 이 게임에서 무엇을 가능하게 해야 하는지 정한다.

이번 단계에서 할 일

핵심 플레이어, 기대 경험, 가장 위험한 가정을 정한다.

  1. 이번 시제품을 볼 플레이어 조건을 정한다. 예: 2D 액션 로그라이트를 플레이해 본 사람.
  2. ‘다양한 플레이 스타일’을 공격 거리·타이밍·이동·표적 선택처럼 실제 행동으로 풀어 쓴다.
  3. 틀렸을 때 영향이 큰 가설부터 고른다. 첫 UI 가설은 파츠 역할 이해와 의도적인 조합 선택이 적절하다.
  4. 무엇을 보면 지지·수정·기각할지 테스트 전에 합의한다. 숫자는 팀이 테스트 규모를 정할 때 확정한다.

가설 A · 이해

플레이어는 도면, 흰색·검정 잉크, 팔레트의 역할을 구분할 수 있다.

관찰 신호: 각 선택을 바꾼 뒤 기본 공격·특수 공격·추가 효과 중 무엇이 달라질지 설명한다.

가설 B · 선택

플레이어는 다음 전투에서 원하는 방식에 맞춰 무기와 팔레트를 구성할 수 있다.

관찰 신호: 선택 이유를 말하고, 예상한 공격과 실제 공격을 연결한다.

이 단계의 결과물 · UX 목표 한 문장, 대상 플레이어, 우선 가설, 사전 판정 기준
03 / 첫 번째 검증

플레이어를 먼저 이해하기

기획자가 예상한 문제와 플레이어가 실제로 겪는 문제를 구분한다.

인터뷰 계획

장르 경험이 있는 3~5명을 첫 반복의 출발 규모로 제안한다.

  1. 최근 플레이한 게임에서 무기나 빌드를 바꾼 장면을 이야기해 달라고 한다.
  2. 새 장비를 비교할 때 먼저 본 정보와 이해하기 어려웠던 용어를 묻는다.
  3. 다른 조합을 시도한 이유, 반복 플레이를 멈춘 이유를 구체적 경험으로 묻는다.
  4. 기록에는 실제 발언과 관찰, 우리 해석을 분리한다. 인터뷰 후 우선 가설을 수정한다.
질문 예: “최근에 무기 구성을 바꾼 때가 언제였나요? 무엇을 보고 바꾸었나요?”
피할 질문: “무기 트리가 있으면 더 재밌을 것 같나요?”
이 단계의 결과물 · 익명 인터뷰 기록, 반복된 불편과 기대, 수정된 가설
04 / 범위층

이번에 만들 최소 경험

모든 메뉴를 만드는 대신, 조합을 고르고 전투에서 확인하는 한 바퀴를 완성한다.

포함 여부를 결정할 질문

“이 화면이 없으면 우선 가설을 확인할 수 있는가?”

정비 진입→도면 선택→흰색·검정 설정→팔레트 선택·채우기→소모 확인·굽기→출발→짧은 전투→복귀

첫 시제품에 포함할 후보

정비 허브, 도면·형태·특수 공격 비교, 팔레트 채우기, 제작 결과와 소모 확인, 현재 구성 요약, 전투 HUD, 정비 복귀.

이번 가설과 별도로 검토

도감, 상점, 장기 성장, 설정, 상세 서사 연출. 필요성이 확인되면 다음 반복에 추가한다.

이 단계의 결과물 · 화면 목록, 화면마다 해야 할 행동, 이번 반복의 제외 목록
05 / 구조층

선택과 정보의 관계 설계

플레이어가 무엇을 먼저 고르고, 어떤 결과를 확인한 다음 출발할지 결정한다.

화면의 논리

무기 관계와 화면 이동은 구분해서 그린다.

시스템 관계

도면 → 흰색 잉크: 형태·기본 공격 / 검정 잉크: 특수 공격. 별도 팔레트 → 지정 색 칸·무색 칸 → 개별 효과 파츠.

팔레트의 동일 효과는 칸마다 독립 발동하며 현재 손에 든 무기 효과만 적용한다.

플레이어 행동

현재 구성 확인 → 도면·잉크·팔레트 변경 예고 → 효과와 소멸 재료 비교 → 확정 또는 취소 → 전투 준비 확인 → 출발.

부분 교체와 새 팔레트 재제작은 손실 범위가 달라 별도 흐름으로 설계한다.

  1. 선택을 바꿀 때마다 현재 상태와 변경 후 상태, 소모 재료를 함께 보여준다.
  2. 팔레트 없이 도면 무기만 쓰는 경로와 일부 칸만 채운 팔레트의 활성화 경로를 열어 둔다.
  3. 단순 교체로 기존 파츠 하나가 소멸하는 경우와 재제작으로 기존 팔레트·색상 파츠 전부가 소멸하는 경우를 구분한다.

06 / 골격층

배치와 조작을 먼저 시험하기

색과 장식을 빼고도 이해되는 화면을 만든다. 정비 UI와 전투 HUD는 별도 과제로 본다.

낮은 충실도 시안

B안: 도면 설정 → 팔레트 제작·정비의 단계식 흐름.

둘 다 현재 구성, 변경 후 효과, 비용과 소멸 재료가 읽혀야 한다.

전투 HUD

현재 무기·보조 무기·체력·특수 공격 상태처럼 전투 판단에 필요한 후보만 배치한다. 정확한 표시 항목은 장착 무기 수와 전투 규칙을 확정할 때 정한다.

실제 게임 장면 위에 놓고 캐릭터·적·지형을 가리지 않는지 본다.

07 / 표면층

잉크와 스케치를 시각 언어로

기존 게임의 분홍·보라 숲과 픽셀 캐릭터에 어울리면서, 선택과 전투 정보를 선명하게 읽히게 한다.

스타일 규칙

표현의 역할을 먼저 정하고 시안을 만든다.

  1. 스케치 선은 도면의 형태, 잉크 번짐은 선택·확정·변화 피드백에 쓴다.
  2. 흰색·검정 잉크, 다섯 색 파츠, 무색 칸은 이름·문양·설명을 함께 써서 구분한다.
  3. 픽셀 게임 화면과 어울리는 정보 패널·글꼴·아이콘 크기를 실제 해상도에서 검토한다.
  4. 동양풍 장식을 기본값으로 두지 않는다. 세계관의 ‘잉크·도면·팔레트’가 보이되 전투 가독성을 우선한다.
이 단계의 결과물 · 시각 방향 2~3개, 선택한 화면 시안, Unity 구현용 색·글꼴·상태 규칙
08 / 두 번째 검증

실제로 고르고, 싸우고, 다시 고르게 하기

‘이해했다’는 말보다 설명 없이 한 선택과 전투 행동을 본다.

테스트와 판정

과업의 목표만 알려주고, 버튼 이름과 경로는 알려주지 않는다.

정비 과업 예시

“다음 전투에서는 적에게 가까이 붙어 빠르게 싸우고 싶습니다. 출발 준비를 해보세요.”

관찰: 어디를 먼저 보는가, 무엇을 비교하는가, 예상한 공격은 무엇인가.

전투 과업 예시

선택한 구성으로 짧은 구간을 플레이한다. 이후 다른 방식으로 바꿔 한 번 더 플레이한다.

관찰: 실제로 공격 거리·리듬이 달라졌는가, HUD를 보고 판단할 수 있었는가.

사용성 판정도면·잉크·팔레트 역할 이해 · 스스로 정비 완료 · 소멸 재료 인지 · 현재 무기 식별
게임 경험 판정형태·특수·추가 효과 차이 체감 · 선택 이유 · 다음 조합을 시도하는 행동

‘몇 번 반복해도 질리지 않는가’는 한 번의 클릭 테스트로 알 수 없다. 짧은 UI 테스트 후 플레이 가능한 빌드에서 여러 차례의 정비→전투 반복을 별도로 관찰한다.
