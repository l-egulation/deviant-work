# Unity 적용 전 전달 자료 최종 대조

검토일 2026-11-13 · 기준 289ae31 · HUD 전체/타이틀 제외. Unity 미변경.
이번 검토는 패키지 파일·ID·좌표와 현행 소스/명세의 대조다. 새 브라우저 전수 조작 검사나 Unity 실행 검사를 수행한 것은 아니다.

## 판정
핵심 화면의 구현 착수 자료는 갖춰졌다. 그러나 모든 화면이 연결까지 완료된 납품 상태는 아니다. 아래 전달 보완과 런타임 계약을 먼저 처리하고, 가방→제작→장비 한 흐름부터 적용하는 것이 적절하다.

## 직접 재검증한 항목
- PNG 원본 52개: 현재 원본·패키지·manifest SHA-256 전부 일치. 누락 0.
- sprite ID 214개: 중복 0, 지정 rect의 원본 경계 초과 0.
- 잉크 43개: 병·효과·조건 참조 ID 누락 0.
- 패키지 분류: 공방 증강39, 봉인 증강12, 무기13, 스킬40, 팔레트 바탕6/칠5 등. 이 숫자는 패키지 등록 수이며 게임의 최종 실행 후보 활성화 검증을 뜻하지 않는다.
- 구현 명세 Markdown 로컬 링크 누락 0. 색인149개 대응표 존재.
- 파일 일치는 시안에 쓰인 원본이 보존됐음을 뜻한다. 폰트/화면/Unity 분할 결과까지 동일하다는 증거는 아니다.

## 전달 전에 보완할 항목
|우선|항목|발견 사항·처리|
|---|---|---|
|높음|봉인 진행 상태 분할|패키지는 seal-progress-v2.png 전체만 등록. CHALLENGES는 세 상태를 요구한다. 원본2172×724, 대기 [0,0,724,724], 현재 [724,0,724,724], 완료 [1448,0,724,724]. world-flows-v1/app.js viewBox와 일치. importer용 상태 ID/rect를 패키지에 추가할 것. 그림 재제작 불필요.|
|높음|공통 입력 예외|README의 일반 F/Esc/QE/WS 규칙을 모든 화면에 일괄 적용하면 충돌. 설정 F/G 확인창은 방향 선택 없음, 이름 입력 Enter/Esc, 지도는 지도 전용키, 월드 방향키는 이동. 개별 명세를 우선하는 입력 모드 표가 필요.|
|높음|모달·시계 소유권|장비 공유10초 대기를 일시정지 중에도 감소시킬지 명세에 확정값 없음. 화면 적용 복귀 타이머는 정지 메뉴에서도 진행해야 함. 시간 종류와 메뉴 입력 차단을 별도 계약으로 정할 것.|

|중간|폰트 전달|폰트 파일은 의도적으로 제외. 로컬 불러오기 방식은 Unity 폰트 설정 완료를 의미하지 않음. 팀의 합법적 폰트 확보와 한글 글리프/줄바꿈 검증 필요.|

## UI별 남은 부분
|범위|상태|
|---|---|
|지도|충전소 십자·적 점·출구 기호가 임시 도형/문자. 이벤트4종 개별/완료 표시 연결 미완료. 기존 승인 에셋 재사용 가능 여부부터 정하고 없는 것만 추가.|
|오프닝|맨손 A키가 검토용 입력. 실제 바인딩·스킵·사망 후 재개·진행 저장 정책 미확정.|
|로딩|1.8초 시안 타이머 대신 실제 장면 완료 연결 필요. 실패/재시도 안내 상태는 없음.|
|결과|Esc로 탐험 시안에 복귀하는 임시 동작을 게임에 복제하면 안 됨. 정산 1회, 다음 챕터/최종 마을 이동 계약 필요.|
|월드 팝업|실제 건물/캐릭터 앵커·화면 경계·동시 팝업 우선순위 미검증.|
|봉인·이벤트|고유 roomId와 보상 지급 상태 연결. 현재 scene 문자열 기반 예시는 같은 종류의 여러 방을 구분하지 못함.|
|보스 소개·소진 알림|타이머는 있지만 최종 CSS에서 애니메이션이 꺼진 부분 존재. 자연스러운 페이드는 Unity에서 별도 확인.|
|작은 화면|앞선 대표 실측10상태와 이후 CSS 대조 문서를 구분. 149개 전체의 960×540 실측 완료로 해석하지 않음.|

## 규칙 적용 우선순위
팀 합의/사용자 확정 → 현행 UI 명세 → 화면별 구현 명세 → 현행 시안. 시안의 검토용 입력·예시 가격·타이머는 게임 규칙이 아니다. 문서가 명시한 미연결 사항을 임의의 새 규칙으로 메우지 않는다.

## 다음 작업 순서
1. 전달 패키지 보완: 상태별 분할 ID, 화면별 에셋 연결표, 입력 모드/복귀표. 기존 그림은 유지.
2. 짧은 결정 시간: 장비 대기 시계, 오프닝 재개/스킵, 로딩 실패 대응. 지도 표시는 기존 에셋 재사용안을 먼저 제시.
3. 위 계약을 반영한 핵심 HTML 흐름 검수: 6칸·긴 설명·입력 예외·작은 화면. 결과 Esc 등 실제로 오해될 시안도 정리.
4. 사용자 승인 후 Unity의 독립 UI 작업 브랜치에서 가방→제작→장비 세 화면 먼저 적용. 공통 프레임/선택/폰트/입력 검증 후 확대.
5. 보상·상점·증강 → 설정·결과 → 마을·월드·이벤트 순서로 연결. 각 묶음에서 저장/재진입/중복 지급/초점 복귀 검사.

HUD 전체와 타이틀은 위 순서에 포함하지 않는다. 전체 UI를 다시 그리는 것보다 전달 계약을 마무리하고 한 흐름을 실제 게임에 맞춰 검증하는 단계다.
