# 상점 증강·봉인 증강

[공통 명세](README.md) · [구매](../sketch-v3/index.html?state=augment) · [3중1택](../sketch-v3/index.html?state=augment-choose) · [선택 대기](../sketch-v3/index.html?state=augment-pending) · [봉인](../sketch-v3/index.html?state=augment-seal) · [보유 증강](../sketch-v3/index.html?state=augment-owned)

코드의 maintenance/‘정비소 증강’은 상점 증강 계열을 가리킨다. 보상·상점 아이템 진열과 다른 후보 풀이다. 현행 런타임 데이터: 상점39종 중 실행용30/대기9, 봉인12종. 대기9종은 에셋이 있어도 실제 후보에 넣지 않는다.

## 구성·배치
구매 진입 → 후보3개 → 획득 결과. 보유 증강은 별도 열람 상태. 봉인은 구매 없이 후보로 진입.

|요소|현재 스타일 기준(1920×1080)|
|---|---|
|콘텐츠|좌우130px, 폭1660px|
|후보|3열, 간격72px, 높이640px; 후보 내부 독립 세로 스크롤|
|후보 안쪽|padding24px, 두 번째부터 좌측48px와 얇은 구분선|
|승인 증강 문양|150×150px, 아래30px|
|이름|34px, 최소44px 높이, 아래36px|
|효과/대가 소제목|27px, 아래24px|
|본문|26px, 행간1.65; 그룹 위34px 여백|
|구매 진입|최대1100px, 상단120px, 문단 위아래32px|
|보유 목록|최대1320px·높이740px 스크롤, 문양90px, 설명과36px 간격|

선택 카드 원색/명도, 비선택 텍스트 .74·이미지 .6, 초점 밝기1.15. 이름 붓칠과 하단 선택 행동의 F 유지. 대가는 옅은 붉은색, 보조 주석은 회색. 안정형에 불필요한 ‘안정적인 성장’ 설명이나 빈 대가 영역을 만들지 않는다.

## 입력
|상태|방향키·F|Esc / W·S|
|---|---|---|
|구매 진입|구매/보유 증강 버튼 이동, F 실행|최상위 닫기는 호출자에 연결|
|후보 선택|←→선택 중 후보 변경, F 획득. ↓행동 줄, ↑카드 복귀|W/S는 확정 전 선택 중 카드 설명 스크롤|
|상점 후보 대기|나중에 선택으로 구매 진입 복귀|Esc도 동일 후보를 남기고 복귀|
|봉인 월드 후보|F로 하나 획득|선택 전 Esc 닫기 차단, 나중에 선택 없음|
|획득 결과|F 확인|상점은 진입 화면, 봉인 월드는 게임 복귀|
|보유 목록|돌아가기 F|W/S 목록 스크롤, Esc 구매 진입|

상단 단계 표시 추가하지 않는다. 비활성 버튼에는 F를 넣지 않는다. 단독 봉인 시안에는 ‘나중에 선택’이 남아 있으나 world-bridge.js 연결에서는 제거된다. Unity 월드 흐름에는 후자를 전달한다.

## 구매·후보 규칙
상점 가격 = 60G + 이번 런 획득 완료 구매 횟수×30G, 최대10회. 실제 가격은 데이터 연결. 현재 구현은 결제 시 후보 저장, 선택 완료 시 구매 횟수 증가. 대기 후보가 있으면 새 결제 없이 이어가기.

- 실행용·미보유 후보 중 안정형1 + 도박형2. 도박형2개는 서로 다른 group.
- 안정형 또는 서로 다른 도박 group 2개를 구성할 수 없으면 후보 부족. 임의 중복 후보로 채우지 않음.
- 골드 부족/최대 구매 횟수/후보 부족은 구매 행동 자체를 비활성화하고 이유 표시.
- 결제 후 닫기·재진입 시 같은 후보 유지. 추가 과금·재추첨 없음.
- 상점 증강 중복 획득 불가. 봉인은 maxStacks 미만만 후보, 획득 후 중첩 증가.
- 봉인 가능 후보가 3개 미만이면 현재 코드는 가능한 수만 제시. 0개면 ‘제안할 증강 없음’ 비활성. 실제 전종/최대 중첩 종료 처리 정책은 게임 연결에서 별도 확인 필요.

## 데이터·구현 경계
augmentId/name/gain/cost/note/group/runtime/maxStacks 및 승인 문양 ID. 상점 보유 ID, 봉인 중첩 수, 구매 횟수, 골드, pendingMaintenance/pendingSeal을 각각 관리한다. 대기 후보는 화면 객체가 아닌 런 상태 소유. 중복 F는 한 번만 처리. 봉인 보상은 일반 보상 기회와 별개.

현재 HTML의 구매 진입 차단 계산은 상점 기준을 공유하므로 봉인 진입 문구까지 그대로 복제하지 않는다. 봉인 진입은 봉인 후보와 중첩 규칙만 참조한다. 획득 결과의 설명 색·대가 전체 재표시는 후보 화면과 일치 여부를 구현 시 검수한다.

## 검수
실행용30/대기9 분리, 안정1·도박2 group, 골드0/10회/후보 부족, 결제 후 Esc 재입장 후보·골드 불변, 반복 F, 봉인 중첩 한도/0후보, 선택 중 W/S, 가장 긴 효과·대가를 960×540에서 끝까지 읽고 행동 줄로 왕복.
