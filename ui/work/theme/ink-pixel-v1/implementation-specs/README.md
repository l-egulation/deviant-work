## 공통 배치
기준 캔버스1920×1080. 화면 전체를 min(가로/1920,세로/1080) 배율로 맞춘다. 960×540에서는 모든 치수가50%. 다른 비율의 여백/중앙정렬은 Unity에서 실제 확인.

|---|---|
|콘텐츠 좌우 여백|130씩, 전체폭1660|
|상단 시작|64|
|가방 본문|x130,y269,width1660,height655|
|제작/장비 본문|x130,y174,width1660,height755|
|가방/장비 열|680 + 중앙140 + 840|

긴 내용은 지정된 상세/목록 영역에서 스크롤. 버튼과 탭을 설명의 overflow 아래로 밀지 않는다. 텍스트 길이를 맞추려고 글자 크기를 자동 축소하지 않는다. 제목-본문 여백을 유지한다.

## 시각 상태
선택과 키보드 초점은 다르다. 다른 영역으로 이동해도 선택 무기/슬롯 값은 유지하지만 현재 조작 영역이 더 밝아야 한다.
- 주 탭: 가방/제작/장비 좌측상단, Q/E. 선택 탭1.12배, 비선택 opacity .56.
- 항목: 비선택 opacity .57 및 낮은 채도, 선택 opacity1. 현재 초점 brightness1.15.
- 팔레트: 비선택 .59/아이콘 .8배, 선택1/1배. 문구에는 승인 붓칠, 아이콘 위 선택 도형 금지.
- 행동: 선택 버튼만 F 및 붓칠. 초점 확대1.07배. 비활성 opacity .4, 실행불가 및 F 없음.
- 비활성 영역: 내용 opacity .65/saturation .6. 비활성 영역과 실행불가 버튼은 구분.
- 잉크 아이콘 단독: 확대·명도만, 별도 선택선 없음.
- 조건 #bed7e5 계열, 효과 #badc9f 계열, 적용값/비용 #e4cf89 계열. 실제 최종 잉크 색 규칙은 content-flows.js/스타일 우선.

## 공통 입력 계약
방향키는 선택/미리보기만 갱신, F는 단계 진입/실행. Esc는 한 단계 뒤로. Q/E는 주탭 전환. W/S는 현재 상세 스크롤(260 논리px 단위). 한글 키보드에서도 물리 KeyF/KeyQ/KeyE/KeyW/KeyS 대응.

Unity에는 화면상 배치를 바탕으로 명시적인 선택 이웃을 설정한다. HTML의 거리 기반 방향 탐색을 그대로 복제할 필요는 없음. 비활성 대상은 실행되지 않으며 마지막 항목에서 초점이 화면 밖으로 유실되지 않아야 한다. 마우스가 정지해 있을 때 키보드 선택을 덮어쓰지 않는다.

## 시안과 실제 연결의 경계
HTML 독립 화면의 최상위 Esc는 stage를 browse로 되돌리며 실제 게임을 닫지 않는다. Unity에서는 메뉴 호출자에게 닫기를 전달하고 원래 게임/보상 초점으로 복귀해야 한다. 월드 연결 시안은 이 연결을 별도 bridge로 시뮬레이션한다.
교체대기 진행 시계·세이브의 초안 보존·런 종료 초기화는 게임 상태가 소유한다. 프레임마다 UI가 임의로 생성/감소시키지 않는다. 명세상 팀 합의와 게임 구현이 다르면 구현 수정 대상으로 기록한다.

## 구현 검수 공통
1920×1080/960×540에서 동일 폰트로 비교. 장문·20자 이름·6칸·43종·빈 목록·비활성·재진입을 확인. 각 화면 최초 초점→이동→F→Esc→재진입, 스크롤 끝, 마우스 혼용을 확인. 기준 이미지는 갤러리의 해당 state 이미지. 기존 HTML 검수와 Unity 적용 후 검수는 별개.
