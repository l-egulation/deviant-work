결론과 검토 범위

남은 작업은 몇 개의 팝업을 추가하는 수준이 아니다. 보상·제작·장비·상점·증강의 규칙을 먼저 재정렬해야 한다. 테마와 기존 에셋은 유지할 수 있지만, 현행 갤러리를 그대로 구현 명세로 넘기면 안 된다.

지정한 팀 저장소의 로컬 HEAD와 문서, 스케치 런 핵심 구현, 현재 UI 소스를 대조했다. 팀 저장소 작업 트리는 깨끗했다. 새 pull이나 원격 브랜치 병합, Unity 수정은 하지 않았다. 이번 검토는 정적 검토이며 Unity 플레이·전체 조작 재시험·모든 화면의 픽셀 단위 검수는 수행하지 않았다. FigJam은 이번에 재조회하지 않았다. 따라서 “전체 UI가 실행까지 검증됐다”는 뜻이 아니다.

이전 검토의 “일반 보상이 즉시 열린다”는 설명은 폐기한다. 현재 팀 문서와 구현은 보상 기회를 저장하고 직접 여는 방식이다. 이전에 남은 것으로 적었던 첫 제작 안내·마을 색 복원·하늘길 기록판은 이미 시안이 있다.

• 탐험: 봉인 석판 진입·진행 3페이지·완료, 실제 포탈 상호작용, 보스 소개와 건너뛰기. 기존 설명용 시안과 혼동하지 말 것.

• 마을·스토리: 시작 마을 이동/추격/조력자/각성/맨손 안내의 실제 대사 연결. 기존 범용 대화창을 재사용하되 각각 새 전체 화면을 만들 필요 없음.

• 결과·전환: 첫 클리어/반복 클리어/마지막 챕터 종료의 목적지, 장면 이동 중 입력 차단과 로딩 표시는 실제 연결 검수 항목.

문서와 구현 자체의 불일치

• 정비소 증강 문서는 내구도 미구현 때문에 9종 제외라고 적지만, 현재 SketchArsenal/SketchRunBinding에는 내구도 누적·파괴 연결이 있다. 내구도가 생겼다는 이유만으로 해당 증강 9종까지 구현됐다고 볼 수 없다. 증강 연결 상태는 별도 확인 대상이다.

• 런타임 문서에는 새 잉크 43종과 강화 수치가 아직 적용되지 않았다고 명시돼 있다. 시안의 잉크 12종과 증강 3종은 전체 목록이 아니다. 문서·제안 데이터·실행 카탈로그를 구분하여 merge 후 ID 기준으로 에셋 대응표를 만든다.

• 이벤트 방 공통 문서는 자유로운 출입과 완료 즉시 선택을 말하지만, 기존 봉인 도전 문서는 철창/상자 열기, 잠긴 상자는 장비 보상 연계 미정을 남긴다. 기존 방까지 새 공통 규칙을 소급할지 확인 필요.

• UI 화면 명세의 2챕터 준비 중 문구와 실제 Chapter2EntryBridge가 공존한다. 화면 명세 한 파일만 보고 결과 버튼을 확정하지 않는다.

• 기존 팔레트 강화·색 변경·스탬프 코드가 남아 있다는 사실만으로 현행에 다시 넣지 않는다. 스케치 런에서 실제로 접근되는 경로를 기준으로 판단한다.

현행 갤러리 분류

유지할 기반: 가방 격자, 제작/장비 분리, 스케치 정보 구성, 상점 기본 레이아웃, 공방 조건 표시, 대화·말풍선, 기록 농가, 우물, 하늘길 기록, 설정·일시정지·지도.

개정 대상: 보상 quota/reward-done/boss/boss-ink, 5칸 제작 샘플, 장비 스왑·내구도, 상점 수치, 증강 구매 흐름, 결과 분기. 이미지는 비교용으로 남겨두되 최신 규칙 확정본이라고 부르지 않는다.

폐기 상태 유지: 옛 스탬프 장착/교체, 칸 강화, 칸 색 변경, 가방 용량 초과 교체, 예전 도면 선택·시작 팔레트 다시 뽑기. 타이틀과 전투 HUD는 사용자 요청대로 보류.

에셋: 잉크·증강 전체 제작은 merge 후 진행. 이번에는 새 문양을 만들지 않았다. 기존 12/3 에셋 보드는 샘플이며 출시 전체 목록이 아니다.

권장 작업 순서와 통과 기준

1. 충돌 8항목 중 보상·완성 후 추가 부여·스왑·클리어 분기를 먼저 확정한다. UI 취향과 게임 규칙을 분리한다.

2. 보상 개정: 0회/7회 이상/전종 보유/가방 복귀/출구 처리까지 동일 후보와 초점이 유지되는지 확인한다.

3. 제작·장비 개정: 1~6칸, 빈 칸 확정, 여러 효과 스크롤, 교체 대기와 맨손, 20자 이름을 960×540에서 검수한다.

4. 상점·증강: 가격 데이터 연결, 미획득 잉크 진열, 구매 제안 보존, 후보 부족과 최대 횟수, 보유 증강 열람을 연결한다.

5. 결과·이벤트: 목적지와 정산을 확정하고, 기존 이벤트 실제 월드 안내를 만든 뒤 새 4종의 공통 목표 표시를 설계한다.

6. 입력 통합 검수: 각 화면의 진입 초점→방향키→F 확정→Esc 복귀→재진입을 실제로 시험한다. 비활성에는 F를 표시하지 않고 선택된 실행 버튼만 강조한다. Q/E와 G 충돌, 스크롤 끝, 마우스 혼용도 확인한다.

7. 콘텐츠 merge 후 전체 ID·효과·강화값·문양 대응표와 에셋을 완성한다. 타이틀/HUD 재개는 별도 결정한다.

현재는 위 목록을 정리한 단계다. 이번 보고서가 시안 수정 완료나 Unity 적용 완료를 의미하지 않는다.

새로 올라온 흐름도 작업 기록

UI 브랜치의 새 커밋 4d5267e도 확인했다. ui/docs/log/2026-11-12.md는 FigJam v3 개정과 와이어프레임 미개정을 기록한다. 이 기록의 공통 내구도 6,500은 이번 기준의 칸 수 비례 내구도보다 이전이며, “잉크를 넣는 순간 고정”은 최초 확정 전 임시 배치와 구분해서 수정해야 한다. 흐름도 실제 캔버스는 이번에 직접 열어 검증하지 않았다.
