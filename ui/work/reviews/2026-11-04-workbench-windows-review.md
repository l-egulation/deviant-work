# 작업대 창 검토 (2026-11-04)

대상: 피그마 「탐색 · 마을 작업대 창」 v3 (보급소 3상태, 염색공방 4상태). 결과는 v4에 반영했다. 설계: [마을 작업대 창 설계](../../docs/specs/2026-11-04-village-workbench-windows.md)

## 진행

1. impeccable critique 방식으로 직접 검토 (닐슨 10개 기준 26/40). 웹 코드 검사기는 피그마에 쓸 수 없어 디자인 검토만 했다.
2. 서로 결과를 모르는 검토자 3명에게 같은 화면을 보였다: 게임 UI 디자이너, 플랫포머 로그라이트 게이머, 조작·접근성 담당.

## 여러 명이 같이 짚은 것 → v4 반영

| 지적 | 누가 | v4 |
|---|---|---|
| 떠 있는 안내창이 트리(다음 칸·연결선)를 가린다 | 3명 모두 | 아래 정보 줄로 옮김 |
| 창을 연 F가 바로 구매로 샐 수 있다 | 디자이너, 게이머, 접근성 | F 길게 눌러 해금, 여는 F를 떼기 전 입력 무시 |
| 안료 부족이 칸에서 안 보인다 | 디자이너, 접근성 | 칸·줄 가격을 빨강 「· 부족」 |
| 챕터 잠김과 앞 칸 잠김이 같은 자물쇠 | 디자이너, 게이머 | 챕터 잠김만 자물쇠 + 「N챕터 보스 뒤」 |
| 960×540에서 글자가 10px 아래로 | 디자이너, 접근성 | 18px 이상 |
| 가격이 세 번 반복 | 디자이너, 게이머 | 칸 옆 + 버튼 두 곳 |
| 보급소 잠긴 줄이 통째로 회색이라 산 단계·가격이 사라짐 | 디자이너, 게이머 | 가격·단계 유지, 조건만 덧붙임 |

## 한 명만 짚은 것

- 방향키 이동 규칙이 없다 (접근성) → 설계 문서에 규칙을 적었다.
- Q/E 탭 키 표시 (접근성) → 탭 줄 양옆에 키 표시.
- 지난 런에서 번 안료를 알고 싶다 (게이머) → 「지난 런 +N」 추가.
- 「무색」이 이득인지 모르겠다 (게이머) → 열린 질문. 팀 규칙 확인 후 문구.
- 창이 크다, 640 폭 제안 (디자이너) → 열린 질문. 18px과 같이 다시 본다.
- 두 건물을 한 화면에서 비교하고 싶다 (게이머) → 보류.

## 팀원 5분 테스트 (제안)

준비: v4 보급소 ①, 염색공방 ③을 화면에 띄우고 말로만 답하게 한다.

1. 보급소를 5초 보고: 지금 살 수 있는 것과 못 사는 것을 말해 보세요. 못 사는 건 왜인가요?
2. 안료 120이 있다면 무엇을 사겠어요? 이유는?
3. 염색공방에서 「팔레트 4칸」을 왜 못 사나요? 다음 런에서 살 수 있을까요?
4. 「무기 2 첫 칸 무색」을 사려면 무엇을 먼저 해야 하나요?
5. 방향키로 「팔레트 4칸」에서 「무기 1 첫 칸 무색」까지 가 보세요 (몇 번 눌렀는지 센다).

기록할 것: 답이 틀린 문항, 머뭇거린 시간, 「이게 뭐예요?」라고 물은 단어.

## 2차: 마을 나머지 화면 (마을 v1 → v2)

같은 검토자 3명에게 회수공방·출발 준비대·기록 농가·귀환 우물·마을 HUD(v1)를 보였다. 결과는 「마을 v2」에 반영했다. 설계: [마을 나머지 화면 설계](../../docs/specs/2026-11-04-village-screens.md)

| 지적 | 누가 | v2 |
|---|---|---|
| 준비대에서 두 개 골라도 「정하기」를 안 누르고 Esc면 잃는다, 매 런 F가 너무 많다 | 3명 모두 | 두 개 고르면 바로 저장, 지난 조합 기억, 버튼 없앰 |
| 기록 초기화 확인이 해금보다 약하다 | 디자이너, 접근성 | F 3초 길게 + 게이지, 첫 포커스는 초기화 아님 |
| 이정표가 출발 못 하는 상황인데 평소와 같다, 안내가 멀리 뜬다 | 디자이너, 접근성 | 미리 「무기 2개 필요」+ F 자물쇠, 안내는 이정표 옆 |
| 우물 말풍선만 규칙이 다르다, 「출발 준비」가 바로 출발인지 헷갈린다 | 3명 모두 | 「무기 고르기 (출발 준비대)」, 말풍선 안 키 안내 |
| HUD 동전 120이 골드인지 안료인지 모르겠다 | 디자이너, 게이머 | 「안료 120」 + 물방울 모양 |
| 흰 외곽선이 밝은 배경에서 안 보인다 | 접근성 | 황토 테두리(포커스와 같은 표시) |
| 「새로 열림」이 색으로만 구분된다, 「(닫힘)」 이유가 없다 | 접근성, 디자이너 | 검은 칩, 닫힘 아래 「1챕터 보스 뒤」 |
| 회수공방 예시가 보급소 예시(보관함 3칸)와 맞지 않는다 | 게이머 | 「먼저: 보관함 2칸 (지금 1칸)」 |
| 출발 전에 이번 런에 가져가는 것을 한눈에 보고 싶다 | 게이머 | 준비대 오른쪽 아래 요약 |
| 무기 공격 방식을 모르고 고른다 | 게이머 | 카드에 공격 설명 한 줄 자리 |
| 준비대 잔액 자리에 출발 골드가 들어가 헷갈린다 | 디자이너 | 잔액 자리는 안료, 골드는 요약으로 |

## 3차: 창 배치 대안 블라인드 비교 (960×540, 테마 색)

피그마 [탐색 · 마을 창 배치 대안](https://www.figma.com/design/qjL5PNYHPgTDQ0huZXBzLg/?node-id=113-75). 같은 내용을 네 배치로 그려 실제 크기(960×540)와 GPT 테마 초안 색(흑연 패널·밝은 글자·청록 포커스)으로 비교했다. 검토자에게는 이름 없이 W/X/Y/Z로만 보였다.

| 안 | 배치 | 디자이너 | 게이머 | 접근성 |
|---|---|---|---|---|
| W | 오른쪽 위 고정 패널 (지금 안) | 1 | 1 | 3 |
| X | 건물 옆 말풍선 창 | 2 | 2 | 2 |
| Y | 화면 위 띠 | 3 | 4 | 4 |
| Z | 가운데 + 배경 어둡게 (Dead Cells·Hades식) | 4 | 3 | 1 |

- W: 위치가 늘 같아 예측하기 쉽고, 위 HUD의 안료와 가격을 한눈에 비교한다. 다른 창(회수공방·준비대·기록 농가)에 그대로 쓴다. 약점은 주인공이 오른쪽에 서면 가린다는 점, 주인공과 창 사이 시선 거리.
- Z: 시선 이동이 가장 짧고 대비가 좋지만 마을과 주인공을 덮고(목표 위반), 안료 HUD가 가려진다.
- Y: 염색 트리가 눌리고 건물 이름표를 가리며, 고른 칸과 설명이 멀다.

**정함 → W'**: W 위치 고정 + 주인공이 화면 오른쪽 절반이면 왼쪽 위로 뒤집기 + 창을 연 건물 이름표를 청록으로 칠해 어느 건물 창인지 연결(X의 장점) + 960 기준 글자 12px 이상, 잠김 글자 대비 올림(#C3CACC), 잠긴 줄도 가격과 조건 두 줄, 선행 조건 줄 되살림, 버튼에 길게 누르기 게이지.

남은 의견: 길게 누르기는 0.4초 정도로 짧게(게이머). 열린 창에서 옆 건물로 넘어가기(게이머) — 보류. 패드 표시(LB/RB, A/B) 바꿔 보이기, 스틱 4방향 고정과 반복 간격(접근성) — 조작 단계에서 정한다.

참고 게임 페이지(gameuidatabase)는 사이트가 자동 읽기를 막아 열지 못했다. 비교는 알려진 패턴(Dead Cells 수집가·Hades 거울 = 가운데 큰 창, Rogue Legacy 2 대장간 = 마을 안에서 바로)으로 했다.
