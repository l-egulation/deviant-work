# 결과 화면 정보 구조 초안

최신 기준: SSAFY 게임 저장소 `S15P31F109/docs/design/run-structure.md`, `docs/development/chapter2-runtime.md`, `docs/design/systems/roguelite-progression.md` (2026-11-03 확인). [현행 사용자 흐름 FigJam](https://www.figma.com/board/nHfGBYZsYIcHNUD9SU4cGs/?node-id=62-377)

## 먼저 바로잡을 흐름

1챕터 보스 처치 → 제단 보상 선택(선택 사항) → 출구 F → 철창 열림·페이드 → **같은 런으로 2챕터 진입**. 이 경계에는 결과 화면과 마을 귀환이 없다. 장비·팔레트·가방·체력·골드는 유지된다. 보스 첫 클리어 해금만 영구 기록된다.

체력 0 → 죽는 모션 → 실제 시간 2.5초 뒤 **사망 결과** → `마을로` → 시작 마을. 현재 마지막으로 구현된 2챕터를 끝냈을 때는 **런 완료 결과** → `마을로` → 시작 마을. 이후 3챕터가 구현되면 최종 결과의 시점은 다시 검토한다.

## 화면 비교

| 항목 | 사망 결과 | 런 완료 결과 |
| --- | --- | --- |
| 첫 문구 | `이번 도전 종료` | `이번 도전 완료` |
| 맥락 | 사망한 챕터 이름. 원인/가해자는 데이터와 표현이 준비되면 추가 | 최종으로 완료한 챕터 이름. 현 빌드는 2챕터 |
| 가장 먼저 볼 정보 | 이번 런에서 얻은 마법안료 | 이번 런에서 얻은 마법안료 |
| 공통 기록 | 플레이 시간, 처치 수 | 플레이 시간, 처치 수 |
| 영구 진행 | 새 해금이 있다면 `시작 마을에서 확인` 안내 | 새 해금이 있다면 `시작 마을에서 확인` 안내 |
| 주 행동 | `마을로` | `마을로` |
| 보조 행동 | 없음. 재도전은 마을에서 준비 | 없음. 재도전은 마을에서 준비 |

## 표시 순서와 동작

1. 결과 제목과 챕터 맥락.
2. 이번 런의 마법안료. `이번 런 +N`과 누적 보유량을 구분해 표기한다. 누적 보유량을 결과 시점에 안정적으로 읽을 수 없다면 `이번 런 +N`만 표시한다.
3. 플레이 시간과 처치 수.
4. 영구 해금이 새로 열렸을 때만 안내 문구. 결과 화면에서 즉시 구매 버튼을 만들지 않는다.
5. `마을로` 한 가지 행동. 버튼을 누르면 시작 마을로 이동한다.

사망 연출 중 결과 화면을 미리 띄우지 않는다. 결과 화면이 열린 뒤 게임을 멈춘다. 마법안료는 처치 시 이미 지급되는 영구 재화이므로 결과 화면에서 다시 지급되는 것처럼 표현하지 않는다. 골드·잉크·장비는 다음 런으로 가져간다는 인상을 주지 않도록 결과 요약의 보유 자산으로 강조하지 않는다.

## 팀 검토가 필요한 항목

- 현재 `2챕터 완료`를 유저에게 `이번 도전 완료`로 부를지, 앞으로 3챕터가 생길 때 `챕터 완료`로 바꿀지.
- 사망 원인/가해자와 클리어 보스 기록을 결과 화면에 넣을 수 있는지.
- 첫 보스 클리어로 열린 해금을 결과 화면에서 구체적으로 보여줄지, 마을에서 처음 보여줄지.
- 결과 화면에서 누적 마법안료를 함께 보여줄지.

## 문서 충돌

게임 저장소의 `docs/design/player-flow.md`와 `docs/design/ui-and-interaction.md`에는 1챕터 클리어 결과 및 바로 마을 귀환을 전제로 한 이전 문구가 남아 있다. 실행 기준인 `run-structure.md`, `chapter2-runtime.md`, `getting-started/playtest.md`와 맞지 않으므로 흐름도와 결과 화면은 후자를 기준으로 했다.
