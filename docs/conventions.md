# 문서 작성 규칙

모든 분야(`ui/`, `assets/`, `story/`)가 같은 문서 틀을 씁니다. 사람(이규재)과 AI 도구(Claude, GPT, Codex) 모두 이 규칙을 따릅니다.

## 갱신 규칙

- **작업이 끝날 때마다** 해당 분야의 `docs/STATUS.md`와 그날의 `docs/log/YYYY-MM-DD.md`를 갱신합니다.
- 무엇을 정했다면 `docs/decisions.md`에 한 항목을 추가합니다.
- 팀 레포 문서를 근거로 판단했다면 `팀 레포 기준: <짧은 커밋> (YYYY-MM-DD)`를 적습니다. 팀 기준은 자주 바뀌므로 날짜가 없는 판단은 나중에 믿을 수 없습니다.
- 루트 공통 파일(`README.md`, `.gitattributes`, `docs/`)은 `main`에서만 고치고, 분야 브랜치는 `main`을 병합해 받습니다.
- 분야 브랜치는 자기 분야 폴더 밖의 파일을 만들거나 고치지 않습니다.
- 이전안·폐기 설정은 지우지 않고 `archive/`로 `git mv`합니다. `archive/README.md`에 보관 이유를 한 줄 적습니다.
- 팀 레포 문서를 복사해 두지 않습니다. 경로와 커밋만 적습니다.

## 파일과 양식

### `docs/STATUS.md` — 지금 상태 (100줄 이내)

```
# <분야> STATUS
갱신: YYYY-MM-DD (기기) · 팀 레포 기준: <커밋> (YYYY-MM-DD)

## 지금 상태
한두 문장

## 진행 중
- 항목 · 위치 링크

## 다음 할 일
1. 우선순위 순 3~5개

## 막힌 것·확인 필요
- …

## 최근 기록
- [YYYY-MM-DD](log/YYYY-MM-DD.md) 한 줄 요약 (최근 3개)
```

### `docs/log/YYYY-MM-DD.md` — 날짜별 작업 기록

```
# YYYY-MM-DD (기기)

## 한 일
## 만들거나 바꾼 파일
## 정한 것 → decisions.md 링크
## 다음에 이어 할 것
```

같은 날 여러 번 작업하면 같은 파일에 `---`로 구분해 덧붙입니다.

### `docs/decisions.md` — 결정 기록 (최신이 위)

```
## YYYY-MM-DD · <결정 제목>
- 결정: …
- 이유: …
- 근거: 팀 레포 <커밋>/<문서>, 사용자 결정, 피그마 링크 등
- 상태: 현행 | 일부 일치(팀 기준과 일부 다름) | 구안(대체됨 → 링크) | 구안(팀 기준과 다름)
```

상태 뒤에 짧은 비고를 괄호나 문장으로 붙일 수 있습니다. 팀 기준과 대조만 한 이전 결정은 `결정`·`이유` 칸 없이 상태와 대조 결과만 적어도 됩니다.

결정이 바뀌면 이전 항목을 지우지 않고 상태를 `구안`으로 바꾸고 새 항목을 위에 추가합니다.

### `docs/handoff.md` — 인수인계

다른 세션·기기·도구가 이어받을 때 읽는 맥락입니다. 역할, 작업물 위치, 주의할 점, 사용자 선호를 적습니다. 자주 바뀌는 상태는 STATUS에 두고 여기에 적지 않습니다.

### `docs/specs/`, `docs/plans/`

설계는 `YYYY-MM-DD-<주제>-design.md`, 작업 계획은 `YYYY-MM-DD-<주제>-plan.md`로 둡니다. 레포 전체에 걸친 설계·계획만 `main`의 `docs/specs/`, `docs/plans/`에 둡니다.

## 커밋

- 메시지: `docs(<분야>): …`, `design(<분야>): …`, `art(<분야>): …`, `chore: …`
- 팀 레포(`S15P31F109`)에는 이 레포의 어떤 것도 push하지 않습니다.
